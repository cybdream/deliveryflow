# 고객용 배송 조회 API

고객은 **주문번호** 또는 **배송 추적번호(운송장번호)** 중 알고 있는 값을 사용해 배송 상태를 조회할 수 있습니다. 두 방식 모두 수령인 전화번호가 일치해야 하며 로그인은 필요하지 않습니다.

> 현재의 배송 추적번호는 DeliveryFlow가 배송을 배정할 때 발급하는 내부 번호입니다. 실제 택배사 운송장번호를 연동하는 기능은 이후 확장 항목입니다.

## 1. 주문번호로 조회

운송장번호를 모르는 고객이 주문번호로 조회하는 방식입니다.

```text
GET /api/v1/tracking/orders/{orderNo}?recipientPhone=010-1234-5678
```

예시:

```text
GET /api/v1/tracking/orders/ORD-20260816-8503?recipientPhone=010-1234-5678
```

## 2. 배송 추적번호로 조회

배송 배정 후 발급된 배송 추적번호를 아는 고객이 조회하는 방식입니다.

```text
GET /api/v1/tracking/shipments/{trackingNo}?recipientPhone=010-1234-5678
```

예시:

```text
GET /api/v1/tracking/shipments/TRK-20260816-12345678?recipientPhone=010-1234-5678
```

## 공통 응답

```json
{
  "orderNo": "ORD-20260816-8503",
  "trackingNo": "TRK-20260816-12345678",
  "status": "IN_DELIVERY",
  "scheduledDate": "2026-08-17",
  "deliveredAt": null
}
```

응답에는 주소, 전체 수령인 전화번호, 사용자 ID, 기사 이메일을 포함하지 않습니다.

## 보안과 예외 처리

- 조회값과 수령인 전화번호가 모두 일치해야 합니다.
- 주문번호나 배송 추적번호가 없거나 전화번호가 일치하지 않아도 동일하게 `404 Not Found`를 반환합니다.
- 따라서 번호만으로 다른 주문의 존재 여부를 확인하기 어렵습니다.
- 전화번호는 `010-1234-5678`처럼 숫자와 하이픈으로 입력합니다.
- 이 기능 적용 전 이미 배정된 배송은 `trackingNo`가 없을 수 있습니다. 이 경우 주문번호 조회를 사용할 수 있습니다.

## 테스트 방법

Swagger UI의 **Customer Tracking** 그룹에서 인증 없이 실행할 수 있습니다. 먼저 관리자 계정으로 배송을 배정한 뒤 응답의 `trackingNo`를 확인합니다. 주문번호와 배송 추적번호 방식 모두 같은 수령인 전화번호로 테스트합니다.
