# PowerShell 통합 테스트

관리자와 기사 계정을 한 대의 PC에서 번갈아 Swagger에 입력하지 않아도 되도록, 핵심 운영 흐름을 순서대로 테스트하는 PowerShell 스크립트입니다.

- 스크립트: `scripts/test-delivery-flow.ps1`
- 비밀번호와 JWT는 파일에 저장하거나 출력하지 않습니다.
- 새 주문과 배송 데이터를 생성하므로, 실행 직전에 `RUN`을 입력해야 합니다.

## 로컬 실행

프로젝트 루트에서 실행합니다.

```powershell
.\scripts\test-delivery-flow.ps1
```

기본 대상은 `http://localhost:8080`입니다.

## Railway 실행

```powershell
.\scripts\test-delivery-flow.ps1 -BaseUrl "https://deliveryflow-production.up.railway.app"
```

관리자와 기사 비밀번호를 각각 입력합니다. 화면에는 표시되지 않습니다.

## 수행 순서

1. 상태 확인 API 호출
2. 관리자와 기사 로그인 및 역할 확인
3. 관리자 주문 등록
4. 기사 배정
5. 기사 본인 배송 목록 조회
6. 기사 배송 시작(`IN_DELIVERY`)
7. 기사 배송 완료(`DELIVERED`)
8. 관리자 배송 이력과 대시보드 조회

## Railway 실행 결과

2026-08-16에 Railway 배포 URL을 대상으로 스크립트를 실행해 관리자 로그인, 주문 등록, 기사 배정, 기사 상태 변경, 이력 및 대시보드 조회까지 성공했습니다. 테스트 데이터의 ID, 계정 비밀번호, JWT는 기록하지 않습니다.
## 결과 해석

성공하면 생성된 주문 ID, 주문번호, 배송 ID, 최종 상태, 이력 건수가 출력됩니다. 토큰과 비밀번호는 출력되지 않습니다.

실행 중 오류가 나면 오류 메시지와 성공한 단계 번호만 확인합니다. 비밀번호나 JWT 값은 공유하지 않습니다.

## 로그인 오류 해결

`401 UNAUTHORIZED`가 나오면 해당 이메일의 현재 데이터베이스 비밀번호가 입력값과 다른 것입니다. 로컬 계정은 최초 실행 때만 생성되므로, `application-local.properties`의 bootstrap 비밀번호를 나중에 바꿔도 이미 만들어진 계정 비밀번호는 자동으로 바뀌지 않습니다. 현재 비밀번호로 로그인하거나, 개발용 데이터베이스에서 해당 계정을 명시적으로 초기화한 뒤 애플리케이션을 다시 실행합니다.
